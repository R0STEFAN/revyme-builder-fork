# Перенесення Framer → Revyme

Цей імпортер читає модель відкритого редактора Framer і створює редагований
React/Next.js source у Revyme. Він переносить сторінки, дизайн-компоненти,
CMS, стилі, адаптивні правила, анімації та зв'язки, які підтримує поточний
адаптер. Поточний перевірений шлях створює нові сторінки й компоненти;
вставлення вибраних шарів у конкретний контейнер та заміна наявної сторінки
ще розробляються.

## Підготовка

1. Запусти локальний Revyme через `npm run dev` і відкрий
   `http://localhost:3333` у Chrome.
2. Збери reader: `node scripts/build-framer-native-extension.mjs dist/framer-native-reader-0.1.8`.
   Збірка створить директорію та ZIP поруч. ZIP треба розпакувати перед
   встановленням.
3. На сторінці керування розширеннями Chrome увімкни режим розробника й
   завантаж директорію `dist/framer-native-reader-0.1.8` через **Load unpacked**.
4. Відкрий проєкт Framer у цьому самому браузері та онови його вкладку.

Reader потребує доступу до поточної вкладки Framer, а також дозволів на
копіювання JSON і його завантаження. Захоплення не змінює source проєкту.
Перевірена структура source — дерево версії 128. Reader 0.1.8 розпізнає
перевірені entrypoint-збірки за engine fingerprint; невідому збірку завершує
діагностикою `EDITOR_BUILD_UNSUPPORTED`.

## Захоплення та імпорт

1. У Framer відкрий потрібну сторінку або компонент. Для всього сайту обери
   у popup reader **Увесь проєкт**, натисни **Захопити дерево**.
2. Перевір статус і діагностики в popup. Кнопка **Копіювати JSON** доступна
   лише для повного capture. **Зберегти JSON** дає копію для перевірки й
   повторення; цей файл містить source-модель, а не готовий код Revyme.
3. У Revyme відкрий проєкт, у який треба імпортувати, та встав скопійований
   JSON клавішами Ctrl+V або Cmd+V поза текстовим полем. Імпортер завершує
   операцію лише після перевірки та збереження source. Створені сторінки
   з'являться в проєкті; якщо маршрут уже зайнятий, імпортер вибере окремий
   префікс маршруту, не перезаписуючи наявну сторінку.
4. Відкрий перенесені сторінки й компоненти у візуальному редакторі. Source
   можна переглянути в редакторі коду та отримати через звичайний експорт
   проєкту. Для автоматизованої перевірки використовуй `codeFiles.read` через
   Revyme CLI/MCP, а не файли з `data/builds/`.

За погодженням для цього перенесення імпортер **явно пропускає** необов'язкові
фільтри сторінки за категорією та користувацькі курсори. Після успішної
операції повідомлення називає пропущені можливості. Інші непідтримані або
неповні source-властивості зупиняють імпорт з діагностикою; вони не
відкидаються мовчки.

## Що вже перевірено і що ще обмежує результат

- Збережений повний capture тестового Walker-проєкту компілюється у 36
  native-файлів без діагностик із двома погодженими типами пропусків. Реальний
  локальний сервер прийняв усі файли через prepare/commit у тимчасовий
  проєкт; `codeFiles.read` повернув збережений шаблон сторінок.
- Окрема сторінка пройшла реальне завантаження JPEG, перетворення на WebP,
  серверне збереження й прив'язку URL у збереженому коді.
- Повний Walker-проєкт ще не пройшов живе завантаження всіх ресурсів: один
  SVG-маск із захопленого source повертає HTTP 404, а його альтернативний
  файловий URL — HTTP 403. Потрібен доступний оригінал або свіже повне
  захоплення цього ресурсу. Візуальна рівність, поведінка у браузері,
  редагування CMS і опублікований runtime ще не підтверджені.
- Встановлення unpacked reader у браузері після цієї збірки не перевірено:
  на час локального аудиту браузерний хост автоматизації був недоступний.

Ці результати стосуються збереженого захоплення й названої збірки редактора.
Інший проєкт або нова внутрішня збірка Framer може потребувати нових адаптерів.
