# Технічний план впровадження E-Commerce на базі Medusa.js v2 у Revyme Builder

> **Документ:** Архітектурний план інтеграції інтернет-магазинів  
> **Цільовий проєкт:** `revyme-builder-fork`  
> **Базова e-commerce платформа:** Medusa.js v2 (Headless Node.js / TypeScript)  
> **Статус:** Схвалено до розробки  
> **Мова:** Українська / Технічна англійська  

---

## 1. Концепція та цілі

### 1.1 Мета проєкту
Перетворити **Revyme** на повноцінний візуальний конструктор сучасних інтернет-магазинів із:
* **Автономним open-source бекендом** (Medusa.js v2), що розгортається без щомісячних відрахувань стороннім платформам.
* **100% контролем над візуальним стилем**: сторінка товару, картка, селектор варіантів, кошик, чекаут та кабінет покупця верстаються прямо на канвасі.
* **Особистим кабінетом покупця**: реєстрація, авторизація, історія замовлень із живим відстеженням статусів доставки, збережені адреси.
* **Next.js 16 / React 19 архітектурою**: генерується чистий код (App Router, Server Components, Server Actions), без застарілих шорткодів чи монолітного PHP.

## 2. Чому WooCommerce застарів і який UX ми пропонуємо

У класичному WordPress + WooCommerce налаштування магазину виглядає архаїчно:
* **Проблема WooCommerce:** стилі розкидані між темою, Customizer, шорткодами `[woocommerce_cart]` та десятками важких плагінів. Змінити вигляд сторінки кошика чи кабінету покупця без знання PHP-хуків (`add_action('woocommerce_before_cart')`) або сторонніх монструозних конструкторів неможливо.
* **Проблема тестування станів:** щоб стилізувати порожній кошик, успішне замовлення або статус "Доставлено", розробник змушений вручну імітувати замовлення в базі даних.

### Наша парадигма: «Framer Headless + Shopify OS 2.0 + Live Canvas Simulator»

| Елемент UX | Як у WooCommerce | Як у Revyme Builder + Medusa |
|---|---|---|
| **Стилізація елементів** | CSS-перевизначення, PHP-шаблони в темі | **Прямий візуальний клік**: клікаєш на кнопку «В кошик» чи ціну і міняєш Padding, Font, Shadow, Flexbox у правій панелі білдера |
| **Кошик** | Окрема статична сторінка або плагінний Ajax-попап | **Headless Slide-Out Drawer або сторінка**: з анімаціями Framer Motion і миттєвим оновленням |
| **Кабінет покупця** | Нудна стандартна таблиця `[woocommerce_my_account]` | **Повністю модульний кабінет**: вкладки замовлень, карток адрес та профілю можна розташувати як завгодно |
| **Симулятор станів (Canvas State Simulator)** | Відсутній (треба оформлювати фейкові покупки) | **Перемикач у білдері**: тумблер `[Порожній кошик | 3 товари | Знижка]` та `[Гість | Авторизований | Замовлення відправлено]` прямо в тулбарі канвасу |

## 4. Особистий кабінет покупця (Customer Account Portal)

Особистий кабінет є обов'язковою частиною магазину. У Medusa v2 модуль `Customer Module` надає розширене API для покупців.

### 4.1 Функціональні розділи кабінету
1. **Автентифікація (`/account/login`, `/account/register`):**
   * Реєстрація: Email, Пароль, Ім'я, Прізвище, Телефон.
   * Безпарольний вхід (Magic Link / Email OTP-код) або стандартний пароль.
   * Відновлення пароля через лист із токеном.
2. **Історія замовлень (`/account/orders`):**
   * Список замовлень із сумами, датами та бейджами статусів: `Pending` (Очікує оплати), `Processing` (Комплектується), `Shipped` (Відправлено), `Delivered` (Доставлено), `Canceled` (Скасовано).
   * Номер ТТН / Трекінг-номер перевізника з клікабельним посиланням на службу доставки.
3. **Детальна сторінка замовлення (`/account/orders/[id]`):**
   * Повний список замовлених товарів із фото, вибраними розмірами/кольорами.
   * Розбивка вартості: товари, знижка по промокоду, вартість доставки, податки, підсумок.
   * Адреса доставки та обраний спосіб оплати.
   * Кнопка завантаження інвойсу / квитанції (PDF).
4. **Адресна книга (`/account/addresses`):**
   * Додавання кількох адрес доставки (дім, робота тощо).
   * Вибір дефолтної адреси для миттєвого автозаповнення в чекауті.
5. **Профіль та безпека (`/account/profile`):**
   * Зміна персональних даних та зміна пароля.

### 4.2 Безпека та робота з сесіями
* **HTTP-Only Cookies:** Токен авторизації клієнта зберігається у захищених `httpOnly` куках через Next.js Server Actions. Жодні токени клієнта не витікають у браузерний JavaScript (повний захист від XSS).
* **Next.js Middleware:** Роути `/account/*` захищені middleware: неавторизованого відвідувача автоматично редиректить на `/account/login?redirect=/account/orders`.

## 5. Візуальне налаштування в Revyme Builder

Щоб білдер був максимально зручним і візуальним, інтерфейс розширюється у трьох ключових місцях:

### 5.1 Ліва панель: Вкладка «E-Commerce»
До панелей Layers, CMS, Assets додається нова системна панель **Store Settings**:
* **Підключення Medusa:**
  * Поле `Medusa API URL` (наприклад, `https://api.mystore.com`).
  * Поле `Publishable API Key` (публічний ключ вітрини Medusa v2).
  * Статус з'єднання: зелений індикатор «З'єднано (24 товари, 3 регіони)» або повідомлення про помилку.
* **Налаштування регіонів і валют:**
  * Вибір основної валюти (USD, EUR, UAH тощо).
  * Форматування цін (розділювач, положення символу валюти).
* **Системні сторінки (One-Click Scaffolding):**
  * Кнопка *«Створити сторінки магазину»*: автоматично генерує в проєкті:
    * `products/[slug].tsx` — сторінку товару;
    * `cart.tsx` — сторінку кошика;
    * `checkout.tsx` — сторінку оплати;
    * `account/orders.tsx` — кабінет покупця.

### 5.2 Верхня панель: «Canvas State Simulator» (Кілер-фіча)
Під час верстки магазину вгорі з'являється плашка симулятора станів:
* **Кошик:** `[ Порожній | 1 товар | 3 товари | З промокодом ]`
  * Дозволяє за 1 клік побачити і налаштувати напис *«Ваш кошик порожній — Перейти до покупок»* або перевірити, як верстка тримає довгі списки товарів.
* **Автентифікація:** `[ Гість | Авторизований покупець (Іван П.) ]`
  * Миттєво перемикає вигляд хедера (кнопка «Увійти» $\leftrightarrow$ аватарка «Мій кабінет»).
* **Замовлення:** `[ В обробці | Відправлено | Доставлено ]`
  * Дозволяє налаштувати бейджі статусів та трекінг прямо на макеті.

### 5.3 Права панель властивостей (Properties Panel)
Коли на канвасі виділено e-commerce компонент, відкриваються спеціалізовані тули:
* **Для `ProductPrice`:** тул форматування — показ ціни зі знижкою (`Compare-at price`), розмір знижки у відсотках, колір акційного бейджа.
* **Для `VariantSelector`:** вибір типу відображення (випадаючий список `Select`, кольорові кружечки `Color Swatches`, прямокутні кнопки `Pills`).
* **Для `AddToCartButton`:** налаштування поведінки при кліку:
  * *Відкрити висувний кошик (Drawer)*;
  * *Перейти одразу на чекаут (Buy Now)*;
  * *Показати спливаюче сповіщення (Toast Notification)*.
* **Для `CartDrawer`:** ширина панелі (px або %), анімація виїзду (зліва/справа), розмиття фону (backdrop blur).

## 6. Каталог Headless-компонентів у Revyme

Всі компоненти реєструються як Code Components у білдері і базуються на чистому HTML/Tailwind, що гарантує повну свободу стилізації через стандартні панелі Revyme (Typography, Spacing, Backgrounds, Borders).

### 6.1 Блоки сторінки товару (Product Suite)
1. `<ProductProvider>` — контекст товару за `slug`.
2. `<ProductGallery>` — головне фото + прев'ю-карусель із зумом.
3. `<ProductTitle>` — назва товару (H1/H2).
4. `<ProductPrice>` — динамічна ціна у вибраній валюті.
5. `<VariantSelector>` — вибір розміру, кольору, матеріалу з автоматичним блокуванням варіантів, яких немає в наявності (Out of stock).
6. `<StockBadge>` — індикатор наявності («В наявності», «Закінчується: залишилось 2 шт»).
7. `<QuantityInput>` — лічильник кількості (`-` `1` `+`).
8. `<AddToCartButton>` — кнопка додавання з підтримкою стану завантаження та вимкненого стану.

### 6.2 Блоки кошика (Cart Suite)
1. `<CartProvider>` — глобальний стан кошика (зберігається в cookie/session Medusa).
2. `<CartTrigger>` — іконка кошика в хедері з бейджем кількості товарів.
3. `<CartDrawer>` — модальне вікно або висувна панель.
4. `<CartItemList>` — список позицій у кошику.
5. `<CartItem>` — рядок товару:
   * Зображення товару;
   * Назва + обраний варіант;
   * Кнопки кількості;
   * Ціна за одиницю та сумарна ціна рядка;
   * Кнопка видалення.
6. `<CartDiscountInput>` — поле для введення промокоду з валідацією.
7. `<CartSubtotal>` / `<CartTotal>` — підсумкові суми.
8. `<CheckoutButton>` — перехід до оформлення.

### 6.3 Блоки кабінету покупця (Account Suite)
1. `<CustomerAuthProvider>` — перевірка сесії покупця.
2. `<LoginForm>` / `<RegisterForm>` — форми авторизації та створення акаунту.
3. `<AccountNavigation>` — меню кабінету (Замовлення / Адреси / Профіль / Вихід).
4. `<OrderList>` — сітка/список замовлень.
5. `<OrderItemCard>` — картка замовлення з кнопками «Деталі замовлення» та «Повторити замовлення».
6. `<TrackingStatusTimeline>` — візуальний таймлайн доставки:
   `[Створено] ───> [Оплачено] ───> [В дорозі (ТТН: 2045...)] ───> [Доставлено]`.
7. `<AddressManager>` — картки збережених адрес із кнопками «Редагувати», «Видалити», «Зробити основною».

## 8. Безпека, оптимізація та SEO

1. **Серверний рендеринг (SSR / ISR) каталогу:**
   * Сторінки товарів рендеряться на сервері Next.js (`generateStaticParams` або ISR з revalidate). Це забезпечує блискавичне завантаження (< 100 мс) та 100 балів у Google Lighthouse.
2. **SEO & Мікророзмітка Schema.org:**
   * Автоматична генерація `Product` та `BreadcrumbList` JSON-LD мікророзмітки: Google одразу бачить ціну товару, наявність та рейтинг у результатах пошуку.
3. **PCI-DSS безпека:**
   * Номери банківських карток ніколи не проходять через сервери Revyme чи Medusa. Використовуються захищені фрейми Stripe Elements, що знімає будь-які ризики щодо фінансових даних.

## 9. Очікуваний результат для бізнесу

Після впровадження цього плану **Revyme** отримає унікальну конкурентну перевагу над іншими конструкторами (Webflow, Framer, Wix):
1. **Безплатний потужний бекенд:** клієнт не платить комісії з продажів платформам на зразок Shopify.
2. **Ніяких обмежень у дизайні:** можливість створити нестандартний UI магазину світового рівня, який неможливо зібрати на шаблонах WooCommerce.
3. **Повноцінний B2C досвід:** покупець має свій кабінет, бачить історію замовлень і статус трекінгу в реальному часі.
