# Керівництво: Новий робочий процес розробки сайтів в Revyme (MCP v2)
## Чистий JSX Дизайн + Автоматичний Транслятор Revyme

> **Канонічний документ архітектури розробки**: описує двоетапний пайплайн (Two-Pass Pipeline), який усуває когнітивне перевантаження AI-агента, повністю звільняє дизайнера від системних обмежень Revyme та гарантує 100% автоматичну генерацію `data-id` ядром платформі.

---

## 1. Діагностика проблеми: чому попередня модель давала збій

У класичній моделі розробки на агента одночасно покладалися несумісні завдання:
1. **Творча робота (UI/UX Дизайн світового рівня):** вибір жанру, естетичної тези, колористики, шрифтових пар (Display + Body), просторового ритму, вау-акценту («The Signature Moment»).
2. **Суворий системний комплаєнс (Oracle Gate & AST):** ручне прописування `data-id` на кожному тезі, заборона чистого CSS `transition`, 12 супутніх токенів для пресетів типографіки, брейкпоінти (1200 / 810 / 390 px).
3. **Передчасна абстракція (Bottom-Up антипатерн):** спроба створити кнопки та картки у вакуумі (`components.create`) ще до того, як зверстана реальна сторінка, що руйнувало просторові пропорції та сітку.

### Наслідок: Prompt-Induced Paralysis (Колапс уваги LLM)
Коли контекст моделі захаращений десятками негативних технічних правил, бюджет уваги витрачається на проходження валідації комcompiler'а, а не на естетику. Дизайн виходить сухим, шаблоновим та примітивним (типовий «AI-slop»).

---

## 2. Нова концепція: Двоетапний пайплайн (Two-Pass Decoupled Pipeline)

Процес чітко розділяється на дві ізольовані фази:

```
┌─────────────────────────────────────────────────────────────┐
│  ФАЗА 1: Творча студія дизайну (Creative Frontend Lead)    │
│  - Повна естетична свобода (Zero Revyme Constraints)        │
│  - Вхід: Бриф користувача, референси, побажання             │
│  - У контексті: ЖОДНИХ інструментів Revyme MCP, Oracle Gate  │
│  - Агент НІКОЛИ не створює data-id                          │
│  - Вихід: DESIGN_MANIFEST.md + чистий семантичний JSX макет │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│  ФАЗА 2: Системний транслятор (Revyme Systems Compiler)     │
│  - Роль: Механічний перенос у Revyme через MCP v2           │
│  - Вхід: Готовий маніфест і чистий JSX з Фази 1             │
│  - Послідовний алгоритм дій:                                │
│    1. tokens.set / tokens.add (палітра кольорів)            │
│    2. fonts.transformNextFont (шрифти Next.js)              │
│    3. typography.set (пресети типографіки)                  │
│    4. presets.set (радіуси, тіні, межі)                     │
│    5. fragments.insert (вставка секцій, авто-data-id)       │
│    6. motion.set / textEffects.set (нативні анімації)       │
│    7. components.extract + variants.create (Top-Down екстракт)│
│    8. observe.screenshot / audit (Closed-Loop перевірка)    │
└─────────────────────────────────────────────────────────────┘
```

## 3. Автоматизація `data-id`: Агент НІКОЛИ не створює їх вручну

### Залізне правило платформи
> **Агент ніколи не додає атрибут `data-id` вручну.** Будь-які вимоги щодо ручного створення `data-id` скасовано.

Revyme автоматично бере створення `data-id` на себе на всіх рівнях:
1. **При вставці секцій (`fragments.insert`):** Вбудований менеджер ідентифікаторів (`IdManager`) автоматично парсить дерево через Babel та присвоює кожному елементу семантичний детермінований ID (`section-1`, `text-2`, `btn-3`).
2. **При отриманні коду (Engine Ingestion & Candidate Normalization):** Функція `autoInjectMissingDataIds` (`src/code/parsing/heal-data-ids.ts`) інжектує `data-id="root"` для кореневого блоку сторінки та семантичні префікси (`section-*`, `text-*`, `btn-*`, `nav-*`, `img-*`) для дочірніх елементів із збереженням усіх символів та форматування.
3. **При операціях запису (`codeFiles.submit`, `modifyProjectFile`, `gateTurnFiles`):** Усі вхідні файли автоматично проходять крізь шлюз авто-інжекції `data-id` перед запуском перевірок Oracle.

## 4. Детальний покроковий алгоритм Фази 2 (Перенесення в Revyme)

Субагент-транслятор виконує суто детерміновані технічні кроки за порядком:

### Крок 1: Реєстрація дизайн-токенів (`tokens.set` / `tokens.add`)
Витягує палітру кольорів із `DESIGN_MANIFEST.md` та записує їх у `app/globals.css`:
```json
{
  "category": "color",
  "name": "bg-canvas",
  "value": "oklch(0.14 0.02 260)"
}
```

### Крок 2: Підключення шрифтів (`fonts.transformNextFont`)
Підключає шрифтову пару безпосередньо в Next.js через Google Fonts API, автоматично прив'язуючи CSS-змінні `--font-display` та `--font-body`:
```json
{
  "family": "Syne",
  "variable": "--font-display"
}
```

### Крок 3: Пресети типографіки (`typography.set`)
Оголошує складені пресети. Завдяки вбудованому словнику `defaultTokens` агенту **не потрібно** вручну перераховувати 12 службових токенів — Revyme генерує їх автоматично:
```json
{
  "name": "display-hero",
  "tag": "h1",
  "values": {
    "font": "var(--font-display)",
    "size": "72px",
    "weight": "700",
    "line-height": "1.05"
  },
  "responsiveTiers": {
    "md": { "size": "48px" },
    "sm": { "size": "36px" }
  }
}
```

### Крок 4: Складені дизайн-пресети (`presets.set`)
Фіксує радіуси карток і кнопок, тіні та рамки:
```json
{
  "category": "radius",
  "name": "card",
  "values": { "radius-card": "16px" }
}
```

### Крок 5: Вставка чистого JSX (`fragments.insert`)
Кожна секція сторінки вставляється як єдиний атомарний JSX-фрагмент:
- Жодних `data-id` у коді!
- Для зв'язку з пресетами типографіки використовуються атрибути `preset="..."` (наприклад, `<h1 preset="display-hero">`, `<p preset="body-lead">`).
- Ревіме самостійно згенерує `data-id`, додасть імпорти (`next/link`, `framer-motion`) та застосує адаптивні стилі.

### Крок 6: Налаштування анімацій (`motion.set` / `textEffects.set`)
Замість сирого CSS `transition` (який відхиляється Oracle), застосовуються нативні інструменти Revyme:
- Кінетична поява заголовка Hero через `textEffects.set`.
- Мікро-інтеракції кнопок і карток (hover scale 1.02, tap 0.98) через `motion.set`.
- Плавний скрол через `siteEffects.smoothScroll.set`.

### Крок 7: Top-Down модуляризація компонентів (`components.extract`)
Компоненти створюються **після** верстки, а не до:
1. Викликається `components.extract` для першої картки чи кнопки в секції:
   ```json
   {
     "name": "BentoCard",
     "sourceFile": "app/page.client.tsx",
     "nodeId": "card-first-id"
   }
   ```
2. Revyme автоматично створює `components/BentoCard.tsx`, виносить варіативний текст у `props` і замінює вузол на інстанс.
3. Інші дублікати карток замінюються через `components.replace`.
4. Для компонента додаються варіанти станів (`variants.create`: Hover, Active).

### Крок 8: Візуальний аудит (`observe.screenshot` / `observe.audit`)
Знімаються перевірочні скріншоти на трьох канонічних брейкпоінтах:
- Desktop: `1200px`
- Tablet: `810px`
- Mobile: `390px`

## 5. Системні інструкції субагентів

### Промпт 1: Creative Art Director (Фаза 1 — Чистий дизайн)
```text
Ти — Creative Frontend Lead & Executive Art Director. Твоє завдання — створити унікальну візуальну концепцію та чистий JSX макет за брифом користувача.

ПРАВИЛА РОБОТИ:
1. Забудь про внутрішні інструменти Revyme, Oracle Gate та data-id. Зараз ти займаєшся виключно чистим дизайном.
2. Ти НІКОЛИ не додаєш атрибути data-id. Вони генеруються автоматично ядром платформи.
3. Сформуй DESIGN_MANIFEST.md:
   - Естетичний жанр (наприклад: Luxury Editorial, Industrial Brutalism, Clean Tech).
   - Колірна палітра (4-5 тонів OKLCH/Hex, жодних чистих #000 або #fff).
   - Шрифтова пара (Display для великих заголовків + Body для читання).
   - The Signature Moment (єдиний головний вау-елемент сторінки).
   - Spacing Rhythm (відступи секцій >= 80px, гармонія відступів).
4. Напиши семантичний чистий Next.js / React JSX для секцій сторінки.
   - Для заголовків і тексту вказуй атрибути пресетів: <h1 preset="display-hero">, <h2 preset="section-title">, <p preset="body-lead">.
   - Використовуй семантичні теги <header>, <section>, <nav>, <button>, <a>.
5. Передай готовий маніфест і чистий JSX субагенту-транслятору для перенесення в Revyme.
```

### Промпт 2: Revyme Systems Compiler (Фаза 2 — Механічна трансляція)
```text
Ти — Revyme Systems Compiler. Твоє завдання — механічно перенести готовий дизайн-маніфест і чистий JSX у Revyme Website Builder через MCP v2.

ПРАВИЛА РОБОТИ:
1. Ти не вигадуєш новий дизайн — ти суворо транслюєш отримані артефакти.
2. Тобі НЕ потрібно створювати або трекати data-id вручну. Revyme інжектує їх автоматично приfragments.insert та нормалізації файлів.
3. Послідовний порядок викликів MCP:
   1) tokens.set — зареєструй палітру кольорів у globals.css.
   2) fonts.transformNextFont — підключи Google Fonts до Next.js.
   3) typography.set — зафіксуй пресети типографіки (Revyme згенерує супутні токени).
   4) presets.set — зареєструй радіуси, тіні та рамки.
   5) fragments.insert — встав чистові секції JSX у app/page.client.tsx (це автоматично створить data-id та імпорти).
   6) motion.set / textEffects.set — налаштуй нативні анімації Revyme.
   7) components.extract / components.replace — винеси повторювані картки/кнопки в компоненти.
   8) observe.screenshot — перевір відображення на 1200px, 810px, 390px.
```

## 6. Чеклист готовності сторінки

- [ ] **Жодного ручного `data-id`**: усі ідентифікатори створені Revyme автоматично.
- [ ] **Жодного сирого CSS `transition`**: анімації працюють через `motion.*` або `textEffects.*`.
- [ ] **Типографіка через пресети**: стилі тексту керуються через `preset="..."` / `typography.apply`.
- [ ] **Адаптивність трьох в'юпортів**: відсутнє горизонтальне прокручування на 390px (Mobile).
- [ ] **Відсутність «AI-Slop Tells»**: немає декоративних `border-l-4`, немає 2px рамок на скруглених картках, відсутні вигадані маркетингові штампи («effortlessly», «seamlessly»).
