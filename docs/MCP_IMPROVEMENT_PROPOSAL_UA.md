## 1. Вступ та контекст дослідження

Під час практичного тестування роботи AI-агентів у двох веб-білдерах — **Revyme** (`revyme-builder-fork`) та **Webstudio** (`webstudio-ai-agent`) — за **ідентичним дизайн-промптом** було виявлено помітну різницю в результатах:
* Сайти у **Webstudio** виходять візуально багатшими, мають тонко налаштовану типографіку, гармонійні відтінені кольори, органічну анімацію скролу та інтерактивні ховер-ефекти на всіх картках і кнопках.
* Сайти в **Revyme** частіше виходять більш пласкими, статичними («дерев'яними»), з простішою структурою та дефолтними кольорами, навіть якщо агент використовує офіційний MCP-міст.

При цьому Revyme має фундаментальну архітектурну перевагу: **його джерелом правди є чистий Next.js/React код**, тоді як Webstudio тримає проект у пропрієтарній внутрішній JSON-схемі.

Цей документ підсумовує результати детального дослідження обох репозиторіїв і пропонує **план модернізації MCP Revyme**, який усуне цей розрив і зробить створення сайтів у Revyme швидшим, якіснішим і значно простішим для AI-агентів.

## 2. Чому Webstudio зараз видає кращий дизайн (Аналіз причин)

Порівняльний аналіз показав, що естетична перевага обумовлена не «розумом» моделей, а чотирма системними факторами:

### 2.1. Наявність спеціалізованих скілів арт-директора (60–70% впливу)
У репозиторії Webstudio (`webstudio-ai-agent/.agents/skills/`) встановлено 5 потужних дизайн-скілів:
1. **`impeccable` (v4.1.2)** — розгорнутий скіл арт-директора:
   - Встановлює жорсткий **«Craft Floor»** (мінімальний рівень якості) та **прямо забороняє типові AI-кліше**: 3 однакові картки в ряд, фіолетові градієнти на темному фоні, центровані hero-секції з розмитими плямами, емодзі замість векторних іконок, плоский сірий текст на темному фоні.
   - Вимагає від'ємний трекінг для великих заголовків (`letter-spacing: -0.02em...-0.03em`), підфарбовування нейтральних кольорів відтінком бренду, оптичні компенсації відступів і обмеження довжини рядків (`65-75ch`).
   - Містить скрипти аналізу колірних палітр (`palette.mjs`, `concept-seed.mjs`).
2. **`design-taste-frontend`**:
   - Накладає **Anti-Default Discipline** (забороняє заїжджені дефолти на кшталт `Inter + slate-900`).
   - Вимагає від агента перед генерацією формулювати *Design Read* (настрій, цільова аудиторія, художній референс).
3. **`frontend-design`**:
   - Навчає агента діяти як провідний дизайнер бутікової студії («клієнт платить за унікальність — візьми один обґрунтований художній ризик»).

**У Revyme:** у каталозі `.agents/skills/` встановлено лише один технічний скіл `revyme-mcp`. Він містить виключно правила парсингу Babel AST, проставляння `data-id` та валідації через Oracle. **Про естетику, кольори та шрифти в ньому немає жодного рядка.**

---

### 2.2. Рівень абстракції MCP: «Кладка цеглин» vs «Монтаж готових секцій»
* **Webstudio MCP (`insert-fragment`):**
  Агент одним викликом інструменту вставляє повноцінний UI-фрагмент (складну Hero-секцію або Bento-grid із 20–40 елементами, бейджами та кнопками). За 4–5 викликів агент збирає цілу сторінку.
* **Revyme MCP (`add_node`, `set_styles`, `set_text`):**
  Інструменти атомарні й низькорівневі. Щоб зібрати таку ж Hero-секцію, агенту потрібно виконати **25–35 послідовних викликів MCP**.
  - *Наслідок:* Агент дуже швидко вичерпує ліміт кроків/уваги або свідомо спрощує дерево верстки до примітивного («контейнер + заголовок + 1 кнопка»), оминаючи деталі, підкладки та декоративні шари.

---

### 2.3. Стилі: Інлайн-стилі проти справжніх CSS-класів із псевдокласами
* **У Webstudio MCP (`create-design-token`, `update-design-token-styles`):**
  Стилі створюються як багаторазові CSS-класи. Інструмент нативно підтримує параметр `state: ":hover"` та `state: ":focus"`. Агент задає для кнопки підйом `transform: translateY(-2px)` і тінь, і всі елементи з цим токеном оживають.
* **У Revyme MCP (`set_styles`):**
  Стилі пишуться безпосередньо в JSX як інлайн-стилі: `style={{ ... }}`.
  - **В інлайн-стилях React неможливо задати `:hover` чи `:focus`!**
  - Щоб зробити ховер, агенту потрібно або вручну обвішувати кожен вузол пропсами Framer Motion (`whileHover`), або писати дизайн-компоненти в коді. Через це більшість створених через MCP елементів залишаються статичними.

---

### 2.4. Когнітивне навантаження (Attention Budget) та «Парадокс чистого коду»
Оскільки джерелом правди в Revyme є реальний TSX-файл, кожен виклик мутації запускає генератор AST і валідатор **Oracle Rules**.
* У результаті **70–80% уваги агента** зайнято думками: *«Чи не впаде парсер Babel?», «Чи всюди є унікальний `data-id`?», «Чи правильні директиви `@container`?», «Чи не заблокує мене Oracle Tier-3?»*.
* Агент функціонує в режимі суворого TypeScript-компілятора, і на візуальну естетику в нього майже не залишається ресурсів.
* У Webstudio агент спілкується з абстрактним JSON API, де всі рутинні перевірки сховані всередині платформи, що дозволяє вивільнити 90% уваги суто на творчість.

## 3. План модернізації Revyme MCP (Roadmap)

На відміну від багатьох систем, Revyme вже має під капотом майже всю необхідну базу. Зокрема, у файлі [`src/code/generation/generator-crud.ts`](file:///home/rost/Документи/revyme/revyme-builder-fork/src/code/generation/generator-crud.ts) функція `addNodeInCode` вже приймає рекурсивний тип `AddNodeDef`, що підтримує дочірні вузли (`children`) та `motionProps` (`whileHover`). Залишається лише відкрити ці можливості на рівні MCP.

```
                    Архітектура високорівневого MCP Revyme
                    
 ┌────────────────────────────────────────────────────────────────────────┐
 │                       AI Agent / Дизайн-директор                      │
 │      Озброєний скілами: impeccable + frontend-design + design-taste     │
 └────────────────────────────────────┬───────────────────────────────────┘
                                      │ Високорівневі декларативні виклики
                                      ▼
 ┌────────────────────────────────────────────────────────────────────────┐
 │                          Нові інструменти MCP                          │
 │  • insert_fragment        — вставка складних секцій за 1 виклик        │
 │  • define_style_token     — пресети з підтримкою :hover / :focus       │
 │  • apply_motion_preset    — готові патерни скролу та мікроінтеракцій   │
 │  • make_responsive        — автоматичний каскад для мобільних екранів  │
 └────────────────────────────────────┬───────────────────────────────────┘
                                      │ Автогенерація data-id, motion.*, CSS
```

### Етап 1: Інструмент `insert_fragment` (Секції за 1 виклик)

Створити інструмент, що дозволяє передавати деревоподібну структуру всієї секції в одному payload:

```ts
// Схема виклику інструменту insert_fragment
{
  "parent_id": "root",
  "name": "Hero Section",
  "fragment": {
    "tag": "section",
    "styles": {
      "display": "flex",
      "flexDirection": "column",
      "alignItems": "center",
      "padding": "120px 24px",
      "gap": "32px"
    },
    "children": [
      {
        "tag": "div",
        "name": "Badge",
        "styles": { "padding": "6px 14px", "borderRadius": "9999px", "backgroundColor": "#f3f4f6" },
        "text": "v2.0 is live"
      },
      {
        "tag": "h1",
        "name": "Title",
        "styles": { "fontSize": "64px", "letterSpacing": "-0.03em", "fontWeight": "700" },
        "text": "Intelligent Design Systems"
      },
      {
        "tag": "button",
        "name": "Primary CTA",
        "styles": { "padding": "14px 28px", "borderRadius": "10px", "backgroundColor": "#09090b", "color": "#fff" },
        "hover": { "transform": "translateY(-2px)", "boxShadow": "0 10px 25px -5px rgba(0,0,0,0.2)" },
        "text": "Get Started"
      }
    ]
  }
}
```

**Що робить білдер усередині:**
1. Рекурсивно генерує стабільні та зрозумілі `data-id` (`hero-section`, `hero-title`, `hero-primary-cta`).
2. Елементи, що мають блок `hover`, автоматично трансформує у `<motion.tag whileHover={...} />`.
3. Викликає `addNodeInCode` і генерує акуратний JSX.
4. Проводить файл через валідатор Oracle.

### Етап 2: Токени стилів зі станами `define_style_token`

Дозволити агенту описувати дизайн-токени не лише як статичні значення кольорів, а як повноцінні класи зі станами:

```json
{
  "name": "card-interactive",
  "base": {
    "backgroundColor": "rgba(255, 255, 255, 0.8)",
    "borderRadius": "16px",
    "border": "1px solid rgba(0, 0, 0, 0.08)",
    "padding": "24px",
    "transition": "all 0.2s cubic-bezier(0.16, 1, 0.3, 1)"
  },
  "hover": {
    "transform": "translateY(-4px)",
    "boxShadow": "0 20px 30px -10px rgba(0, 0, 0, 0.1)",
    "borderColor": "rgba(0, 0, 0, 0.15)"
  }
}
```

У Revyme це може транслюватися або у вбудовані пресети білдера (`presets.json`), або у відповідний варіант дизайн-компонента чи глобальний CSS-модуль.

---

### Етап 3: Високорівневі анімаційні патерни `apply_motion_preset`

Замість вимоги до моделі пам'ятати специфіку синтаксису Framer Motion (`initial`, `whileInView`, `viewport={{ once: true }}`, `transition`), надати готовий інструмент:

```json
{
  "node_id": "features-grid",
  "preset": "stagger-children",
  "options": {
    "delay": 0.12,
    "distance": "24px",
    "direction": "up"
  }
}
```

**Базовий набір пресетів:**
* `fade-up` — плавна пружинна поява заголовків при скролі.
* `stagger-children` — послідовна поява сітки карток з красивим інтервалом.
* `lift-on-hover` — підйом картки та посилення тіні при наведенні.
* `bento-glow` — динамічне м'яке підсвічування рамки картки.
* `parallax-slow` — плавне відставання фону при скролі.

---

### Етап 4: Автоматичний мобільний каскад `make_responsive`

Усунути необхідність ручного прописування складних пар `!important` для зміни напрямку Flexbox між десктопом і мобільним:

```json
{
  "node_id": "hero-split",
  "mode": "stack-on-mobile",
  "breakpoint": 768,
  "options": {
    "gap": "20px",
    "reverse": false
  }
}
```

Генератор Revyme самостійно згенерує коректний синтаксис `@container` або медіа-правило в TSX, гарантуючи 100% проходження тестів Oracle Rules.

### Етап 5: Інтеграція арт-директорських скілів у репозиторій Revyme

Це крок, який дає миттєвий ефект навіть до доопрацювання коду:
1. Скопіювати скіли `impeccable`, `frontend-design` та `design-taste-frontend` з каталогу `/home/rost/Документи/webstudio-umami-docker/webstudio-ai-agent/.agents/skills/` у `.agents/skills/` репозиторію Revyme.
2. Доповнити головний `AGENTS.md` правилами пріоритету: перед тим як писати код чи викликати MCP, агент зобов'язаний завантажити скіл `impeccable` та сформулювати концепт згідно з правилом *Craft Floor*.

## 5. Підсумок

Модернізація MCP Revyme поєднує **найкраще з обох світів**:
1. **Зручність і швидкість Webstudio:** AI-агент оперує великими смисловими блоками, токенами та пресетами, спрямовуючи всю свою увагу на композицію, кольори та візуальне враження.
2. **Незрівнянна сила Revyme:** результатом роботи залишається відкритий, красивий, сучасний React-код Next.js без vendor lock-in.
