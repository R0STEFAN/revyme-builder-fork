# Revyme Oracle: Complete Diagnostic & Rule Reference

This document is the comprehensive index of **all 216 architectural and dialect rules** enforced by the Revyme Oracle validator (`src/code/oracle/`).

Whenever files are generated or modified via MCP tools (`revyme_submit_files`, `revyme_insert_fragment`, `revyme_agent_tool`, etc.), the Revyme Oracle runs static AST checks to guarantee that every React/Next.js component is 100% round-trip editable in the visual builder chrome and iframe canvas.

---

## Oracle Rule Severity Tiers

| Tier | Severity | Effect on File Write | Description |
|---|---|---|---|
| **Tier 3** | **Fatal / Block** | **Rejected immediately** | Critical syntax error, missing import, undeclared identifier, or dialect breach that would crash React, break Babel AST parsing, or render a white-screen. |
| **Tier 2** | **Error / Compatibility** | **Rejected** | Violates visual canvas invariants, responsive contracts, layer hierarchies, or variant/interaction state models. Must be fixed to preserve visual editability. |
| **Tier 1** | **Warning / Dialect** | **Reported** | Non-standard styling patterns, suboptimal DOM structure, or minor dialect departures. |

## Top 10 Most Critical Rules (Quick Reference)

Before writing any component or layout, ensure you satisfy these 10 invariants:

1. **`COMPONENT_ROOT_POSITION`**: The component root master must NEVER have `position: 'sticky'`, `position: 'fixed'`, or `width: '100%'`.
   - *Fix*: Keep root `position: 'relative'` with explicit px width/height (or `'auto'`). Instances on the page stretch with `width: '100%'`.
2. **`ROOT_STYLE_SPREAD`**: The component root's inline style object MUST end with `...style`.
   - *Fix*: `style={{ position: 'relative', width: '100%', ..., ...style }}`.
3. **`ANIMATEPRESENCE_POPLAYOUT_MODE`**: `<AnimatePresence>` must include `mode="popLayout"`.
   - *Fix*: `<AnimatePresence mode="popLayout">`.
4. **`ANIMATEPRESENCE_CHILD_LAYOUT` & `ANIMATEPRESENCE_KEY`**: Direct conditional children inside `<AnimatePresence>` must have `layout={true}` and `key="<data-id>"`.
   - *Fix*: `<motion.div key="header-mobile-drawer" layout={true} ...>`.
5. **`VARIANT_VISIBILITY_CONDITION`**: Never use boolean flags like `{isOpen && ...}` or `{isMobile && ...}`.
   - *Fix*: Only use exact variant comparison: `{variant === 'menu-open' && ...}`.
6. **`FLEX_CHILD_MISSING_ORDER` & `FLEX_CHILD_SHRINKS`**: All flex children must carry explicit ordering and shrink resistance.
   - *Fix*: Always add `order: '0', flex: '0 0 auto'` to flex items.
7. **`CSS_TRANSITION`**: Do NOT write inline CSS transitions like `transition: 'all 0.3s ease'`.
   - *Fix*: Use Framer Motion `initial`, `animate`, `whileHover`, and `transition={{ type: 'spring' }}`.
8. **`ATTR_ORDER_DATA_ID_FIRST`**: Place `data-id` and `data-name` FIRST on every tag, before `style` and motion props.
   - *Fix*: `<div data-id="card-root" data-name="Card" style={{ ... }}>`.
9. **`COMPONENT_CHILD_FIXED_WIDTH`**: Never hardcode the component artboard width (e.g. `1200px`) on inner spanning containers.
   - *Fix*: Use `width: '100%'` with optional `maxWidth: '1200px'`.
10. **`TEXT_EXPRESSION`**: The text editing tool cannot edit computed JavaScript expressions like `{`$${price}/mo`}`.
    - *Fix*: Write text as clean string literals, or bind expressions via `revyme_bind_expression` (`item.<field>`).
